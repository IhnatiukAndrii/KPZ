# Генератор QR-кодів

Повноцінний веб-додаток для генерування, управління та збереження QR-кодів. Додаток написаний з використанням React (Next.js), Tailwind CSS, TypeScript, бази даних PostgreSQL через Prisma та Docker.

## Функціонал програми
- **Створення QR-кодів**: підтримка звичайного тексту, URL-посилань, електронних листів, телефонів, візиток (vCard) та Wi-Fi.
- **Кастомізація**: можливість зміни кольору фону, кольору QR-коду, розміру та рівня корекції помилок.
- **Особистий кабінет**: реєстрація та авторизація користувачів (JWT).
- **Організація даних**:
  - Розподіл по папках (можливість створення вкладених папок).
  - Надання та фільтрація по тегах.
  - Позначення QR-кодів як "обраних".
- **Завантаження**: можливість зручно скачати готовий QR-код.
- **Статистика**: перегляд статистики по згенерованих типах.

## Запуск програми локально (Docker)

Для легкого запуску додатка використано технологію контейнеризації Docker.

1. Переконайтеся, що на Вашому ПК встановлено **Docker** та **Docker Compose**.
2. Відкрийте термінал у корені папки з проєктом.
3. Виконайте команду для збірки та запуску контейнерів у фоновому режимі (режим розробника з Hot-Reload увімкнено):
   ```bash
   docker compose build app --no-cache && docker compose up -d
   ```
4. Дочекайтеся закінчення збірки.
5. Відкрийте у браузері: `http://localhost:3000`

## Programming Principles

Під час розробки застосунку дотримувались такі принципи конструювання ПЗ:

1. **DRY (Don't Repeat Yourself)**
   - Компоненти UI (наприклад, кнопки `Button.tsx` чи поля вводу `Input.tsx`) використовуються по всьому коду з перевикористанням розмітки CSS на основі Tailwind, що дозволяє не дублювати базові стилі форм.
2. **KISS (Keep It Simple, Stupid)**
   - Замість важких NextAuth бібліотек, реалізовано просту та надійну вбудовану систему авторизації на основі *JWT* у `middleware` та HTTP-Only файлах cookie (файл `src/lib/auth.ts`).
3. **YAGNI (You Aren't Gonna Need It)**
   - Проєкт містить чітко поставлений функціонал без надлишкової і гіпотетично "можливої в майбутньому" бізнес-логіки.
4. **SRP (Single Responsibility Principle)**
   - Файли маршутизатора API (`app/api/*`) розділені та відповідають лише за конкретний ресурс: `route.ts` в папці `folders` займається лише папками, `tags` — тегами. Логіка генерації QR повністю інкапсульована у `src/lib/qr-generator.ts`.
5. **SoC (Separation of Concerns)**
   - Проєкт розділений на структурні шари: UI (`components/`), бізнес-логіка та валідація (`lib/validators.ts`), маршрутизація та обробка HTTP-запитів (`app/api/`) та база даних (`prisma/schema.prisma`).

## Design Patterns

У коді використано наступні патерни проєктування (Design Patterns):

1. **Singleton (Одинак)** — [src/lib/prisma.ts](src/lib/prisma.ts)
   - *Пояснення*: У Next.js під час роботи (특히 в dev режимі) застосунок може перекомпілюватися. Щоб уникнути створення незліченної кількості з'єднань із базою даних PostgreSQL при кожному ререндері чи HTTP-запиті, об'єкт клієнта Prisma обгортається у Singleton (глобальну константу), яка гарантує, що клієнт буде підключено до бази строго один раз.
   
2. **Provider / Dependency Injection** — [src/context/AuthContext.tsx](src/context/AuthContext.tsx)
   - *Пояснення*: Використано контекст React для "ін'єкції" доступу до даних авторизації у будь-який компонент застосунку (через хук `useAuth`). Це вирішує проблему *Prop Drilling* (необхідності прокидувати змінні з горішнього компоненту дочірнім через десятки рівнів).

3. **Strategy (Стратегія)** — [src/lib/qr-generator.ts](src/lib/qr-generator.ts)
   - *Пояснення*: функція `formatQrContent(data: Partial<QrFormData>)`. Завдяки патерну, залежно від вхідного типу QR-коду (Wi-Fi, текст, email, візитка тощо), всередині функції динамічно обирається відповідна логіка-стратегія (алгоритм правильного форматування тексту/JSON у потрібний для сканера QR-рядковий формат `VCard`, `WIFI:T:WPA;...` тощо) без громіздких дублювальних методів.

## Refactoring Techniques

Під час створення та покращення проєкту були використані класичні техніки рефакторингу:

1. **Extract Component (Виділення компонента)**
   - Великий інтерфейс сторінки 'Dashboard' (дашборд) було розділено на дрібні спеціалізовані компоненти (`QrCard.tsx`, `QrList.tsx`, `QrDetails.tsx`).
2. **Extract Function Method (Виділення методу/функції)**
   - Повторюваний код перевірок авторизації з API route'ів був винесений у загальні хелпери, такі як `verifyAuth` або валідатори схем введення через бібліотеку Zod (`src/lib/validators.ts`).
3. **Replace Magic Number with Symbolic Constant (Заміна магічних чисел символічними константами)**
   - Усі початкові конфігурації генератора (колір фону `#ffffff`, рівень помилок `M`, розмір) були винесені у типізований об'єкт та масиви в файлі `src/lib/constants.ts` (наприклад `DEFAULT_QR_CONFIG`).
4. **Rename Variable / Meaningful Naming (Описові імена)**
   - Замість `e` або `res` використано читабельні імена `qrDataUrl`, `errorCorrectionLevel`, `payload`, що різко підвищує розуміння коду без коментарів.
5. **Consolidate Conditional Expression / Guard Clauses (Консолідація умов та Захисні вирази)**
   - Уникання надмірної вкладеності 'if/else'. Якщо при генерації не передано вміст `if (!data) return ...`, маршрут миттєво віддає помилку HTTP 400 за допомогою Zod-валідації замість побудови "кишки" вкладених умов.
